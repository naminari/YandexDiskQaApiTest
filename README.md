# Yandex Disk REST API Autotest Project

## Описание

Проект автоматизированного тестирования для REST API Яндекс.Диска (https://cloud-api.yandex.net/v1).
Функции покрывают основные операции с тремя группами ресурсов API: Disk (информация о диске),
Resources (папки и файлы) и Trash (корзина).

`BaseTest` - базовый класс: конфигурация RestAssured, токен, ожидание async-операций
`CreateDirTest`, `DeleteFileTest`, `SaveFileTest`, `GetResourceMetaTest` - тесты по ресурсам Диска
`GetDiskInfoTest` - тесты общей информации о диске
`AuthNegativeTest` - тесты авторизации
`.env` - конфигурация токена (не коммитится)
`pom.xml` - конфигурация Maven

## Установка

### Требования
- Java 17+
- Maven 3.8+

### Шаги установки

1. Клонируйте репозиторий:
```bash
git clone https://github.com/naminari/YandexDiskQaApiTest.git
```

2. Установите зависимости:
```bash
mvn install
```

## Конфигурация

В файле `.env` настраивается токен тестового аккаунта:

```
YANDEX_DISK_TOKEN=<oauth-токен полигона>
```

Базовый URL API (`https://cloud-api.yandex.net/v1`) задан константой `BASE_URL` в `BaseTest` и не
требует дополнительной конфигурации.

## Запуск тестов

### Все тесты
```bash
mvn test
```


### Тесты конкретного класса
```bash
mvn test -Dtest=CreateDirTest
```

### Конкретный тест-метод
```bash
mvn test -Dtest=CreateDirTest#testCreateDirPositive
```

### С подробным выводом
```bash
mvn test -X
```

## Описание тестовых классов

### GetDiskInfoTest
Проверка получения общей информации о диске (`GET /disk`): объём диска, занятое место, данные
пользователя.

### GetResourceMetaTest
Метаинформация о конкретном ресурсе (`GET /disk/resources`): позитивный сценарий, фильтрация полей
через параметр `fields`, поведение при отсутствующем ресурсе (404) и пустом `path` (400).

### CreateDirTest
Создание папок (`PUT /disk/resources`): позитивный сценарий, создание с именем на границе лимита
длины (255 символов), превышение лимита, создание уже существующей папки (409), создание в
несуществующем родительском каталоге, имя с юникод-символами.

### DeleteFileTest
Удаление файлов (`DELETE /disk/resources`, `DELETE /disk/trash/resources`): удаление пустого и
большого файла, отсутствие обязательного параметра `path`, удаление несуществующего файла,
перемещение в корзину без `permanently=true`, повторный запрос на удаление во время выполнения
асинхронной операции.

### SaveFileTest
Загрузка файлов: сохранение файла на Диск по внешней ссылке (`POST /disk/resources/upload`),
поведение при недоступном источнике (операция завершается статусом `failed`), а также прямая
двухшаговая загрузка локальных данных (`GET /disk/resources/upload` -> `PUT` по полученной ссылке).

### AuthNegativeTest
Проверка авторизации: запрос без заголовка `Authorization`, запрос с невалидным токеном - оба
случая ожидают `401`. Проверяется один раз на простом эндпоинте (`GET /disk`), так как авторизация
- сквозной слой, общий для всех методов API.
